# motion — Greater Türkiye animasyon motoru

Kısa jeopolitik video kartları üreten motor: dönen kabartmalı küre, ülke ve ittifak vurgusu, haber
kartı. Videolar veri setindeki kaynaklı kayıtlardan **otomatik** üretilir.

A motion engine for short geopolitical video cards — a relief globe, country and alliance
highlights, a news card — produced **automatically** from the sourced records of the dataset.

**Durum / Status:** M1 ve M2 çalışıyor: harita WebGL2'de (ülke kimliği dokusu, tek geçişte
dolgu, sabit kalınlıkta yumuşatılmış sınırlar), video tarayıcının kendi kodlayıcısıyla (WebCodecs) doğrudan
MP4'e yazılıyor; desteklenmeyen yerde ffmpeg yolu devrede. Kabartma ETOPO1 normal haritasından,
gölgelendiricide kuzeybatı ışığıyla (Imhof) hesaplanıyor; gücü her stilde ayrı (`relief`, `limb`).
İlk tam video hazır: `karadeniz-gemi`, 22 sn, kanca → nerede → ne oldu → ne kadar yakın → durum →
veri setinden bağlam, son kare ilk kareye döner (döngü). Plan: [PLAN.md](PLAN.md). Yedi stil, hepsi seçilebilir (A–D ilk dört yön, E/G/K araştırmadan):
[docs/mockups](docs/mockups) (`tasarimlar-hepsi.png`: her stil için kanca, NATO ve kapanış karesi).

## Kullanım / Usage

```bash
npm ci
python tools/data/fetch_emblems.py --sync     # 406 arma, bayrak ve amblem; manifest'teki hash'lerle doğrulanır (Commons'ta silinen ya da değişen dosya uyarıyla atlanır, video o amblemsiz çizilir)
python tools/data/build_relief.py             # yalnızca kabartmayı yeniden üretmek için (depoda hazır: assets/data/relief.png)
npm run dev                                   # önizleme: http://localhost:5178/?scene=hook-karadeniz&style=A
npm run render -- --all-styles                # out/hook-karadeniz-{A,B,C,D}.mp4, 1080x1920, 60 fps
npm run render -- --scene karadeniz-gemi --all-styles   # tam video, 22 sn, yedi stil
node tools/scene/generate.mjs --datasets ../datasets --latest 5   # en yeni 5 kayıttan sahne: scenes/auto/
node tools/scene/generate.mjs --datasets ../datasets --id evt_…     # tek kayıttan
npm test                                      # iki ayrı işlemede aynı kareler (tolerans: 2/255)
```

### v2: Three.js motoru / the Three.js engine

`v2.html` + `src/v2/main.ts`: haritanın üç boyutlu hâli, kürenin yanında ikinci bir sayfa. Aynı
`window.motion` arayüzünü verir (`ready`, `frame(i)`), bu yüzden aynı dışa aktarıcıyla çizilir:

```bash
npm run render -- --page v2.html --scene nufus-2025     # out/nufus-2025-v2B.mp4
npm run dev    # önizleme: http://localhost:5178/v2.html?scene=nufus-2025
```

Sahneler `scenes/v2/*.json`: süre, kamera anahtarları (`at` boylam/enlem ya da `province`, `dist`,
`tilt` dikeyden derece, `az` güneyden derece), satırlar (`*vurgu*`) ve il etiketleri. Kamera bir anda
tek bir hareket yapar, yumuşak başlar ve biter, sonra durur; her satır blok imleçle yazılır (sahibin
2026-10-25 isteği). Kaynak satırı ve doğrulama durumu her karede.

İlk tasarım, **B "Yükselen Türkiye"**: 81 il, 2025 nüfusu kadar yükselen sütunlar (TÜİK ADNKS 2025;
il sınırları geoBoundaries TUR ADM1, OpenStreetMap'ten, CC BY-SA 2.0). Veri: `assets/data/tr-adm1.json`
(0,01 dereceye yuvarlanmış), `assets/data/tr-population-2025.json`.

**D "Şehre iniş"** (`scenes/v2/istanbul-levent.json`, `src/v2/city.ts`): İstanbul'un üstünden Levent'e
iniş. Zemin Sentinel-2 cloudless 2016 (EOX, CC BY 4.0), geniş ve ayrıntılı iki görüntü; binalar
OpenStreetMap'in taban çizgileri (ODbL), kayıtlı yükseklikleriyle (`height`, yoksa `building:levels` x 3,2 m,
yoksa 9 m), odaktan dışa halka halka yükselir; alçak güneş uzun gölge düşürür. Veri:

```bash
python tools/data/fetch_city.py istanbul-levent 28.985 41.065 29.06 41.115   # OSM binaları, Overpass
python tools/data/fetch_s2.py istanbul-levent 28.985 41.065 29.06 41.115 15  # ayrıntılı uydu görüntüsü
python tools/data/fetch_s2.py istanbul-wide 28.55 40.8 29.5 41.35 12         # geniş uydu görüntüsü
```

Bir kompleksin tüm sınırına yazılmış kule yüksekliği (100 m üstü, 10.000 m² üstü taban) düşürülür;
kulelerin kendisi `building:part` olarak gelir. Yalnızca 2016 katmanı CC BY; sonraki yıllar CC BY-NC-SA, kullanılmaz.

### Voice approval

The non-production Fish Speech audition gate is documented in [docs/voice-lab.md](docs/voice-lab.md).
It writes four listening candidates only; it does not change the production TTS path or publish a video.

### Kaggle Fish S2 Pro

Set `MOTION_TTS_ENGINE=kaggle-fish` to produce the narration with Fish Audio S2 Pro on Kaggle GPU and return its WAV files to the normal release pipeline. The secret `KAGGLE_AVAIBLE_TOKEN` (the new Kaggle account, 2026-10-23) authenticates the official Kaggle CLI, passed to it as `KAGGLE_API_TOKEN`; the old `KAGGLE_API_TOKEN` secret belongs to @trnntr and is never used, and the client refuses any account listed in `KAGGLE_BLOCKED_ACCOUNTS` (default `trnntr`) before pushing anything, so the run falls back to OmniVoice instead; the client derives the token owner's dataset and kernel slugs on its first run, then versions the private input dataset for each story, pushes the kernel, downloads `voice-artifact.zip`, then renders and publishes normally. Because the kernel slug is fixed, `kernels status` reports whatever version ran last, so the client first waits for the freshly pushed run to actually start (a non-terminal status) before it accepts "complete" and downloads — otherwise it would grab the previous run's artifact while the new version was still registering, which once shipped a prior English clip under a Turkish video (English voice, Turkish text). The kernel is a Kaggle *script* [tools/voice-lab/kaggle-fish-s2-pro.py](tools/voice-lab/kaggle-fish-s2-pro.py) (a notebook loses its kernelspec on push and papermill then refuses to start it); it needs Kaggle's **2x T4** accelerator — the language model alone nearly fills one 15 GB card, so the script keeps it on the first GPU and puts the codec on the second, and it patches Fish's loader to cast to the inference dtype on the CPU before moving to the GPU (otherwise the fp32 weights briefly overflow a T4). Because the s2-pro config declares a 32768-token context, Fish's cache setup would preallocate a ~4.5 GiB KV cache on the first card — on top of the ~9 GiB language model that leaves no room for the prefill of a ~20 s reference clip, and generation OOMed mid-decode — so the script also caps the cache to a 4096-token context, which frees ~3.9 GiB and is ample for a one- or two-sentence narration segment read from one reference. It clones fish-speech pinned to the `v2.0.0-beta` tag — the s2-pro ("Speech 2") line, whose `transformers<=4.57.3` matches the kernel's pin; the default branch has since moved to `v3.0.0-beta` (transformers 5, tokenizers 0.23), which an unpinned clone would pull and fail to install against the s2-pro setup. The GPU accelerator must be enabled on the Kaggle account, which requires phone verification — otherwise Kaggle ignores the GPU toggle, runs the kernel on CPU, and the job fails its CUDA check. When the Kaggle run fails — most often because the account's weekly GPU quota is spent ("The pushed Kaggle kernel never started a new run") — the Turkish narration is made again with OmniVoice and then Edge TTS, the same chain as `omnivoice-edge`, so a spent quota no longer stops every production; the run fails only if all three fail.

To stop every run re-downloading and re-converting the ~11 GiB model, publish the weights once as a private Kaggle dataset: `KAGGLE_API_TOKEN=… python tools/voice-lab/kaggle_model_bf16.py` downloads `fishaudio/s2-pro`, casts its float weights to bfloat16 (about half the size) and uploads them, then prints a slug. Set the organization variable `FISH_MODEL_DATASET` to that slug and the production kernel loads the model straight from `/kaggle/input` with no download or conversion; left unset, the kernel downloads from Hugging Face as before, so a fresh account still works with no manual step. Before synthesis the spoken text passes through [tools/voice-lab/tr_tts_prep.py](tools/voice-lab/tr_tts_prep.py), which rewrites Latin acronyms and foreign spellings into Turkish graphemes (`USS` → "Yu Es Es", `Washington` → "Vaşington", `F-16` → "ef on altı", `Su-35` → "Su otuz beş") so Fish stays in Turkish and never slips into an English accent mid-sentence; it changes pronunciation only, never a fact, and the on-screen scene and `clips.json` keep the original text. Sampling is tuned for a calm, even delivery — temperature 0.7, top-p 0.7, top-k 20, fixed seed (overridable with `FISH_TEMPERATURE`, `FISH_TOP_P`, `FISH_TOP_K`, `FISH_SEED`); the upstream `inference.py` CLI exposes no repetition-penalty or CFG flag. The copy editor (`tools/scene/nim-copy.mjs`, asking Gemini first, then Hugging Face's router (`HF_TOKEN`, `HF_TEXT_MODEL`), then NVIDIA NIM, through [tools/scene/llm.mjs](tools/scene/llm.mjs)) runs before this step and rewrites `out/narration.json` in place, so Fish reads the freshly generated copy. It turns the clipped on-screen facts into flowing spoken Turkish: the gate keeps every number and proper noun tied to the source (and to the deterministic original), but allows framing and discourse words so the narration reads like a news reader rather than a label, and it writes the on-screen hook as the news itself (two lines of 18 and 24 characters, no type label such as "GAZZE / RESMİ AÇIKLAMA"), gated the same way: every number and proper noun from the source; an edited hook carries `hook.edited`, and scene validation then skips its word-by-word source check for the hook only (the facts block stays strictly source-worded). It also writes the YouTube title (`post_title`, ≤ 70 characters) used by the captions. Gemini (`GEMINI_API_KEY`, `GEMINI_TEXT_MODEL`, default `gemini-3.8-flash`, then `gemini-flash-latest`) answers in seconds; NIM, fixed to `google/gemma-4-31b-it`, gets 60 s (it timed out three times at 180 s on 2026-10-26). When neither key is set or neither answers it logs a CI warning and keeps the generator's copy (PLAN.md section 44).

**YouTube is off until a channel is connected.** There are two channels, one per language: the Turkish **@ConflictGridTR** and the English **@Conflict-Grid**. Both use the same OAuth client (organization secrets `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`), but each has its own refresh token because a token is bound to the channel the owner picked when authorizing: `YOUTUBE_REFRESH_TOKEN` for the Turkish channel, `YOUTUBE_REFRESH_TOKEN_EN` for the English one (`YOUTUBE_PRIVACY_STATUS` optional, default `unlisted`). Mint each token once with [tools/post/youtube-oauth.mjs](tools/post/youtube-oauth.mjs): with the client id and secret in the environment, `node tools/post/youtube-oauth.mjs` opens Google's consent screen, you pick the channel on the "choose a brand account" screen, and it prints that channel's refresh token. [tools/post/youtube-upload.mjs](tools/post/youtube-upload.mjs) takes a trailing channel key and selects the matching client, token and snippet language (`CHANNELS` in the script): `tr` and `en` for the Conflict Grid pair, and `gt` (@greaterturkiye), `defence` (@greaterdefence), `numbers` (@geocompetitions) and `earth` (Greater Earth) for the Greater Türkiye family, which was authorized through a second OAuth client of the same Google project (secrets `YOUTUBE_GT_CLIENT_ID`, `YOUTUBE_GT_CLIENT_SECRET`, and `YOUTUBE_<CHANNEL>_REFRESH_TOKEN`; a refresh token only works with the client that minted it); until a channel's token is set it logs a CI warning and skips, and the step is `continue-on-error` so a missing channel never fails a run. No channel is connected by default — the videos live on the GitHub release and the Pages site regardless.

**Analytics.** [.github/workflows/analytics.yml](.github/workflows/analytics.yml) runs every morning (05:17 UTC) and [tools/post/youtube-analytics.mjs](tools/post/youtube-analytics.mjs) reads each connected channel through the YouTube Analytics API. It commits `analytics/<channel>/latest.json` and a dated copy to the `analytics-data` branch, with:
- per video, the last 90 days: views, engaged views, average view percentage and duration, likes, comments, shares, subscribers gained, title and publish date;
- the channel's daily totals;
- the retention curve of the 20 newest videos.

Since 31 March 2025 a Shorts view counts every start and replay; engaged views keep the older definition and are the number to compare over time. Studio's "viewed vs swiped away" share is not in the API.

Reading analytics needs the `yt-analytics.readonly` and `youtube.readonly` scopes, which tokens minted before 2026-10-25 lack. The OAuth helper now asks for them, and until a channel is re-minted it is skipped with a warning. Run `node tools/post/youtube-oauth.mjs --save <SECRET>` once per channel, with that channel's client id and secret in the environment; `--save` writes the token straight into the repository secret through `gh` instead of printing it. Kill switch: `MOTION_ANALYTICS=off`.

The English channel carries the same record, in English. Rather than re-implement the Turkish scene generator in English, the English track translates the finished Turkish scene and narration: [tools/scene/translate.mjs](tools/scene/translate.mjs) asks NIM (the same fixed `google/gemma-4-31b-it`) to translate every on-screen string and spoken segment — telling the model the exact item counts and re-rolling the call a few times (nudging the temperature up) when the translation comes back the wrong length, invents a number, or will not validate, rather than losing the whole English track to one bad roll — rebuilds `source_text` so the scene still validates, and [tools/scene/refit.mjs](tools/scene/refit.mjs) scales the whole timeline (and the camera path) by the one factor that keeps every block readable, with a frame to spare so rounding to the frame never leaves the tightest block short, because English copy runs longer than Turkish at the same timings. It introduces no number the source does not state, and on any failure writes nothing — so the Turkish video always ships and only the English upload is missed, to be retried next run. The on-screen labels (`WHERE`, `STATUS`, `HOW CLOSE TO TÜRKİYE`, …) switch on the scene's `lang` in [src/templates/video.ts](src/templates/video.ts); the English voice is Kokoro-82M (Apache-2.0 weights, ONNX Runtime on the CPU runner, voice `bf_emma` by default; `vars.KOKORO_VOICE` and `vars.KOKORO_SPEED` change it), made by [tools/audio/tts.py](tools/audio/tts.py) with `TTS_LANG=en` and checked clip by clip with Whisper in English like the Turkish voice; the model files are fetched from the kokoro-onnx release, checked against pinned SHA-256 hashes and cached. Kokoro reads acronyms (`IDF`, `UAVs`) correctly as written, and the thousands separator is dropped before synthesis because it read "1,470" as "one, 470". Setting `vars.MOTION_EN_TTS_ENGINE=kaggle-fish` uses the cloned timbre speaking English instead (`kaggle_submit.py --lang en`), with Kokoro taking over when Kaggle fails. Because the Fish voice is prompted with Turkish clips, Fish read a capital I with Turkish letter values (the pronoun "I" as "ı", "UK" with Turkish letter names), so the English text first passes through [tools/voice-lab/en_tts_prep.py](tools/voice-lab/en_tts_prep.py): "I" → "Ay", letter-read acronyms → their English letter names in the graphemes the prompt reads best (`UK` → "yu key", `IAEA` → "ay ey i ey"), word acronyms kept (`NATO`, `ISIS` → "Aysis"); pronunciation only, never a fact, and the screen keeps the original text; the posting text is [captions.mjs](tools/post/captions.mjs)'s English builder, whose title is the source's own English headline (`meta.title_en`) when the record keeps one, not the hook's capitalised label. The English video renders in its own style (`vars.MOTION_EN_STYLE` pins one; unset, the first style of the story's pool that neither the Turkish cut nor the Turkish channel's last four videos used; falling back to the scene's style if the English copy does not fit), so it does not repeat the Turkish upload frame for frame (PLAN.md section 35). `produce.yml` runs this as a trailing, `continue-on-error` block after the Turkish video: translate → English narration (Kokoro, or Fish when chosen) → render → upload to `@Conflict-Grid`.

**@greaterturkiye** (English war and conflict shorts) has a story of its own: [.github/workflows/produce-gt.yml](.github/workflows/produce-gt.yml) starts after each successful production, at most every ten hours, and takes the next-best record — the one the Turkish channel did not take, so no story is told on two English channels. It uses the same generator, red lines and checks, in the short story order (`kisa`), translated like the English track, voiced by Kokoro (`vars.MOTION_GT_VOICE`, default `bf_emma`), rendered in the scene's own style, the first of its pool that the channel's last four videos did not use (`vars.MOTION_GT_STYLE` pins one; the old fixed `B` made the channel one navy map after another). It is released as `gt-<record>`, which `produce.yml` counts as published, uploaded with the `gt` key, and added to the videos page. Kill switch: `MOTION_GT=off`.

**Earthquakes** go out as instant stories on two channels: [.github/workflows/produce-quake.yml](.github/workflows/produce-quake.yml) runs every 15 minutes and [tools/scene/quake.mjs](tools/scene/quake.mjs) picks each channel's biggest unpublished quake of the last 6 hours.
- **The owner's Türkiye channel** reads Kandilli Rasathanesi's list. The threshold is M ≥ `vars.MOTION_QUAKE_TR_MIN` (default 3.8). The video is Turkish, in the light relief style `Q`.
- **Greater Earth** reads the USGS worldwide feed (public domain). The threshold is M ≥ `vars.MOTION_QUAKE_EARTH_MIN` (default 5.5). The video is English, in style `A`.

The camera goes from the whole Earth to the country, then the province, then the epicentre in the hook's first two seconds.

For Türkiye, [tools/scene/arrivals.py](tools/scene/arrivals.py) computes the first P- and S-wave arrival at the 81 province centres with TauP (ObsPy) and the IASP91 Earth model, from the quake's depth and distance. The `waves` block then draws both fronts where the model puts them, never as a ring growing at a constant speed, sped up so the farthest named city is reached in about six seconds. Each named province lights with its arrival time (`ANKARA · 1 dk 25 sn`). The fronts spread from the first frame, under the hook (`from: 0` on the `waves` block), and the first frame is the country with the epicentre, not a globe; the camera eases out a little while they spread and the last frame is the first (the loop; the owner, 2026-10-26: nothing happened in the first three seconds). Greater Earth gets the same fronts, computed out to 2,500 km with `arrivals.py --no-provinces`, in the light quake style `Q` (style A's black night hid the land). The block types one model arrival (`Ankara: ~1 dk 25 sn`) instead of a running clock, and style `Q` types every line with a cursor over Kenney clicks. The screen and the posting text say that these are model estimates, not felt shaking.

The voice is Kaggle Fish only, on its own Kaggle job (`KAGGLE_JOB_SUFFIX=quake`, so it never overwrites a production's narration). When Kaggle cannot run, nothing is published and the next run tries again. The sound is the Kenney kit with a tick as each named province lights; there is no music.

Each video is released as `quake-<channel>-<id>` and uploaded with the `earth` key, or with `own` once `YOUTUBE_OWN_REFRESH_TOKEN` exists for the owner's channel (mint it with `youtube-oauth.mjs --save YOUTUBE_OWN_REFRESH_TOKEN`). Kill switches: `MOTION_QUAKE=off`, `MOTION_QUAKE_TR=off`, `MOTION_QUAKE_EARTH=off`.

**Sound, all channels**: `assets/sound/kit-kenney.json`, Kenney's CC0 effects ([assets/sound/kenney](assets/sound/kenney)): an opening hit, a woosh on each block change, ticks and pops. There is no music bed (owner, 2026-10-25).

**@greaterdefence** shows the coming space launches: [.github/workflows/produce-defence.yml](.github/workflows/produce-defence.yml) starts after each successful production, at most every ten hours, and [tools/scene/launch.mjs](tools/scene/launch.mjs) asks Launch Library 2 (The Space Devs; free, no key) for the launches of the next 48 hours and takes the most newsworthy one not yet published (Türkiye's payloads first, then crews, new rockets, government missions). The scene is English and in style `D` (`vars.MOTION_DEFENCE_STYLE` overrides it): the pad on the globe with a rocket symbol, the rocket and payload, then an `orbit` block ([src/render/orbit.ts](src/render/orbit.ts)) that draws the climb out of the pad, one revolution of the ground track at the orbit's inclination, and the orbit's height as a ring at the Earth's own scale (the camera pulls back far enough to hold a geostationary ring). Launch Library 2 gives the orbit type, not its elements, so the height and inclination are typical values for the type and the screen and the posting text say so. Voice: Kokoro (`vars.MOTION_DEFENCE_VOICE`, default `bm_george`). It is released as `defence-<scene>`, which is also the ledger of launches already told, and uploaded with the `defence` key. No launch with a drawable orbit in the window is a normal outcome, not a failure. Kill switch: `MOTION_DEFENCE=off`.

The voice Fish clones is the owner's own recording, listed as one or more clips in [assets/voice/references.json](assets/voice/references.json) with each clip's exact transcript; the WAVs live in `assets/voice/references/` and the recordings are Greater Türkiye's, rights reserved. `kaggle_submit.py` ships the reference clips whose WAVs are present to the private Kaggle job dataset and passes them as `--prompt-audio`/`--prompt-text` pairs. It uses one clip by default (the first listed): each extra prompt lengthens the language model's context and KV cache on the first T4, and three ~20 s clips overran it and errored the kernel, so `FISH_MAX_REFERENCES` must be raised deliberately to clone from more than one. Transcripts must match their audio and are never run through the Turkish pre-processor. Until a listed WAV exists the pipeline falls back to the single root `referans.wav`, so adding the recordings under `assets/voice/references/` is the only step needed to switch the production voice.

## Issues

Issues here are worked by Claude Code in GitHub Actions through the org-wide workflow ([Greater-Turkiye/.github](https://github.com/Greater-Turkiye/.github#issues-are-worked-by-claude), called from `.github/workflows/claude.yml`): a new issue is assigned to the owner and resolved end to end; the `claude` label or an `@claude` comment starts it again. Only people with write access can start it.

Buradaki issue'lar GitHub Actions içinde Claude Code tarafından çözülür: yeni issue sahibine atanır ve baştan sona çözülür; `claude` etiketi ya da `@claude` yorumu yeniden başlatır.
