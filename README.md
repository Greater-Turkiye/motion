# motion — Greater Türkiye animasyon motoru

Kısa jeopolitik video kartları üreten motor: dönen kabartmalı küre, ülke ve ittifak vurgusu, haber
kartı. Videolar veri setindeki kaynaklı kayıtlardan **otomatik** üretilir.

A motion engine for short geopolitical video cards — a relief globe, country and alliance
highlights, a news card — produced **automatically** from the sourced records of the dataset.

**Durum / Status:** M1 ve M2 çalışıyor: harita WebGL2'de (ülke kimliği dokusu, tek geçişte
dolgu, sabit kalınlıkta yumuşatılmış sınırlar), video tarayıcının kendi kodlayıcısıyla (WebCodecs) doğrudan
MP4'e yazılıyor; desteklenmeyen yerde ffmpeg yolu devrede. Kabartma ETOPO1 normal haritasından,
gölgelendiricide kuzeybatı ışığıyla (Imhof) hesaplanıyor; gücü her stilde ayrı (`relief`, `limb`).
İlk tam video hazır: `karadeniz-gemi`, 22 sn, kanca → nerede → ne oldu → ne kadar yakın → durum →
veri setinden bağlam, son kare ilk kareye döner (döngü). Plan: [PLAN.md](PLAN.md). Yedi stil, hepsi seçilebilir (A–D ilk dört yön, E/G/K araştırmadan):
[docs/mockups](docs/mockups) (`tasarimlar-hepsi.png`: her stil için kanca, NATO ve kapanış karesi).

## Kullanım / Usage

```bash
npm ci
python tools/data/fetch_emblems.py --sync     # 406 arma, bayrak ve amblem; manifest'teki hash'lerle doğrulanır
python tools/data/build_relief.py             # yalnızca kabartmayı yeniden üretmek için (depoda hazır: assets/data/relief.png)
npm run dev                                   # önizleme: http://localhost:5178/?scene=hook-karadeniz&style=A
npm run render -- --all-styles                # out/hook-karadeniz-{A,B,C,D}.mp4, 1080x1920, 60 fps
npm run render -- --scene karadeniz-gemi --all-styles   # tam video, 22 sn, yedi stil
node tools/scene/generate.mjs --datasets ../datasets --latest 5   # en yeni 5 kayıttan sahne: scenes/auto/
node tools/scene/generate.mjs --datasets ../datasets --id evt_…     # tek kayıttan
npm test                                      # iki ayrı işlemede aynı kareler (tolerans: 2/255)
```

### Voice approval

The non-production Fish Speech audition gate is documented in [docs/voice-lab.md](docs/voice-lab.md).
It writes four listening candidates only; it does not change the production TTS path or publish a video.

### Kaggle Fish S2 Pro

Set `MOTION_TTS_ENGINE=kaggle-fish` to produce the narration with Fish Audio S2 Pro on Kaggle GPU and return its WAV files to the normal release pipeline. The organization secret `KAGGLE_API_TOKEN` authenticates the official Kaggle CLI; the client derives the token owner's dataset and kernel slugs on its first run, then versions the private input dataset for each story, pushes the kernel, downloads `voice-artifact.zip`, then renders and publishes normally. Because the kernel slug is fixed, `kernels status` reports whatever version ran last, so the client first waits for the freshly pushed run to actually start (a non-terminal status) before it accepts "complete" and downloads — otherwise it would grab the previous run's artifact while the new version was still registering, which once shipped a prior English clip under a Turkish video (English voice, Turkish text). The kernel is a Kaggle *script* [tools/voice-lab/kaggle-fish-s2-pro.py](tools/voice-lab/kaggle-fish-s2-pro.py) (a notebook loses its kernelspec on push and papermill then refuses to start it); it needs Kaggle's **2x T4** accelerator — the language model alone nearly fills one 15 GB card, so the script keeps it on the first GPU and puts the codec on the second, and it patches Fish's loader to cast to the inference dtype on the CPU before moving to the GPU (otherwise the fp32 weights briefly overflow a T4). Because the s2-pro config declares a 32768-token context, Fish's cache setup would preallocate a ~4.5 GiB KV cache on the first card — on top of the ~9 GiB language model that leaves no room for the prefill of a ~20 s reference clip, and generation OOMed mid-decode — so the script also caps the cache to a 4096-token context, which frees ~3.9 GiB and is ample for a one- or two-sentence narration segment read from one reference. It clones fish-speech pinned to the `v2.0.0-beta` tag — the s2-pro ("Speech 2") line, whose `transformers<=4.57.3` matches the kernel's pin; the default branch has since moved to `v3.0.0-beta` (transformers 5, tokenizers 0.23), which an unpinned clone would pull and fail to install against the s2-pro setup. The GPU accelerator must be enabled on the Kaggle account, which requires phone verification — otherwise Kaggle ignores the GPU toggle, runs the kernel on CPU, and the job fails its CUDA check.

To stop every run re-downloading and re-converting the ~11 GiB model, publish the weights once as a private Kaggle dataset: `KAGGLE_API_TOKEN=… python tools/voice-lab/kaggle_model_bf16.py` downloads `fishaudio/s2-pro`, casts its float weights to bfloat16 (about half the size) and uploads them, then prints a slug. Set the organization variable `FISH_MODEL_DATASET` to that slug and the production kernel loads the model straight from `/kaggle/input` with no download or conversion; left unset, the kernel downloads from Hugging Face as before, so a fresh account still works with no manual step. Before synthesis the spoken text passes through [tools/voice-lab/tr_tts_prep.py](tools/voice-lab/tr_tts_prep.py), which rewrites Latin acronyms and foreign spellings into Turkish graphemes (`USS` → "Yu Es Es", `Washington` → "Vaşington", `F-16` → "ef on altı", `Su-35` → "Su otuz beş") so Fish stays in Turkish and never slips into an English accent mid-sentence; it changes pronunciation only, never a fact, and the on-screen scene and `clips.json` keep the original text. Sampling is tuned for a calm, even delivery — temperature 0.7, top-p 0.7, top-k 20, fixed seed (overridable with `FISH_TEMPERATURE`, `FISH_TOP_P`, `FISH_TOP_K`, `FISH_SEED`); the upstream `inference.py` CLI exposes no repetition-penalty or CFG flag. The NVIDIA NIM rewrite (`tools/scene/nim-copy.mjs`) runs before this step and rewrites `out/narration.json` in place, so Fish reads the freshly generated copy. It turns the clipped on-screen facts into flowing spoken Turkish: the gate keeps every number and proper noun tied to the source (and to the deterministic original), but allows framing and discourse words so the narration reads like a news reader rather than a label, while the on-screen hook stays strictly source-worded. The model is fixed to `google/gemma-4-31b-it` (not read from an env var), and the call retries on an overloaded endpoint (HTTP 429/5xx) rather than dropping the rewrite on the first 529. When `NVAPI` is unset or the rewrite still fails it logs a CI warning and keeps the deterministic narration.

**YouTube is off until a channel is connected.** There are two channels, one per language: the Turkish **@ConflictGridTR** and the English **@Conflict-Grid**. Both use the same OAuth client (organization secrets `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`), but each has its own refresh token because a token is bound to the channel the owner picked when authorizing: `YOUTUBE_REFRESH_TOKEN` for the Turkish channel, `YOUTUBE_REFRESH_TOKEN_EN` for the English one (`YOUTUBE_PRIVACY_STATUS` optional, default `unlisted`). Mint each token once with [tools/post/youtube-oauth.mjs](tools/post/youtube-oauth.mjs): with the client id and secret in the environment, `node tools/post/youtube-oauth.mjs` opens Google's consent screen, you pick the channel on the "choose a brand account" screen, and it prints that channel's refresh token. [tools/post/youtube-upload.mjs](tools/post/youtube-upload.mjs) takes a trailing `tr`/`en` argument and selects the matching token and snippet language; until a track's token is set it logs a CI warning and skips, and the step is `continue-on-error` so a missing channel never fails a run. No channel is connected by default — the videos live on the GitHub release and the Pages site regardless.

The English channel carries the same record, in English. Rather than re-implement the Turkish scene generator in English, the English track translates the finished Turkish scene and narration: [tools/scene/translate.mjs](tools/scene/translate.mjs) asks NIM (the same fixed `google/gemma-4-31b-it`) to translate every on-screen string and spoken segment — telling the model the exact item counts and re-rolling the call a few times (nudging the temperature up) when the translation comes back the wrong length, invents a number, or will not validate, rather than losing the whole English track to one bad roll — rebuilds `source_text` so the scene still validates, and [tools/scene/refit.mjs](tools/scene/refit.mjs) scales the whole timeline (and the camera path) by the one factor that keeps every block readable, because English copy runs longer than Turkish at the same timings. It introduces no number the source does not state, and on any failure writes nothing — so the Turkish video always ships and only the English upload is missed, to be retried next run. The on-screen labels (`WHERE`, `STATUS`, `HOW CLOSE TO TÜRKİYE`, …) switch on the scene's `lang` in [src/templates/video.ts](src/templates/video.ts); the English voice is the same cloned timbre speaking English (`kaggle_submit.py --lang en`). Because that voice is prompted with Turkish clips, Fish read a capital I with Turkish letter values (the pronoun "I" as "ı", "UK" with Turkish letter names), so the English text first passes through [tools/voice-lab/en_tts_prep.py](tools/voice-lab/en_tts_prep.py): "I" → "Ay", letter-read acronyms → their English letter names in the graphemes the prompt reads best (`UK` → "yu key", `IAEA` → "ay ey i ey"), word acronyms kept (`NATO`, `ISIS` → "Aysis"); pronunciation only, never a fact, and the screen keeps the original text; the posting text is [captions.mjs](tools/post/captions.mjs)'s English builder. `produce.yml` runs this as a trailing, `continue-on-error` block after the Turkish video: translate → English Fish narration → render → upload to `@Conflict-Grid`.

The voice Fish clones is the owner's own recording, listed as one or more clips in [assets/voice/references.json](assets/voice/references.json) with each clip's exact transcript; the WAVs live in `assets/voice/references/` and the recordings are Greater Türkiye's, rights reserved. `kaggle_submit.py` ships the reference clips whose WAVs are present to the private Kaggle job dataset and passes them as `--prompt-audio`/`--prompt-text` pairs. It uses one clip by default (the first listed): each extra prompt lengthens the language model's context and KV cache on the first T4, and three ~20 s clips overran it and errored the kernel, so `FISH_MAX_REFERENCES` must be raised deliberately to clone from more than one. Transcripts must match their audio and are never run through the Turkish pre-processor. Until a listed WAV exists the pipeline falls back to the single root `referans.wav`, so adding the recordings under `assets/voice/references/` is the only step needed to switch the production voice.

## Issues

Issues here are worked by Claude Code in GitHub Actions through the org-wide workflow ([Greater-Turkiye/.github](https://github.com/Greater-Turkiye/.github#issues-are-worked-by-claude), called from `.github/workflows/claude.yml`): a new issue is assigned to the owner and resolved end to end; the `claude` label or an `@claude` comment starts it again. Only people with write access can start it.

Buradaki issue'lar GitHub Actions içinde Claude Code tarafından çözülür: yeni issue sahibine atanır ve baştan sona çözülür; `claude` etiketi ya da `@claude` yorumu yeniden başlatır.
